A data quality check is a rule that runs against a table and fails when the data breaks it: not null, unique, accepted values, ranges, referential integrity, freshness. This explainer covers the check types, why the check should live in the pipeline that produces the table, and how to add checks to a pipeline with Bruin, dbt, Great Expectations, or Soda.
